# TeamSpeak9 重构路线图

## 1. 总体方向

TeamSpeak9 不是 TeamSpeak 6 官方客户端的克隆，而是一个独立的三端产品，用于实现：

- Android 客户端
- Windows / macOS / Linux 桌面端
- 服务端适配层

重点是：

- 完全脱离 TeamSpeak 官方应用
- 依赖我们已经写好的技术栈和协议
- 屏幕共享继续保持现有 MSS / WebRTC 方案
- 手机端和桌面端 UI 参考官方风格，但不绑定官方实现

## 2. 三端目标

### 手机端

- 频道树、用户列表、聊天、设置、语音控制
- 语音通话使用 TeamSpeak 原生协议（ts3j + Opus）直连服务器，与官方服务端互通
- 屏幕共享通过 MSS/WebRTC 实现发布/观看
- UI 采用官方 TeamSpeak 的视觉语法：深色主题、左侧频道树、右侧内容区、底部控制栏

### 桌面端

- 仿照官方 TeamSpeak 客户端布局
- 频道树、用户列表、服务器列表、聊天区、屏幕共享区
- 支持共享方、观看方切换，并接入自有信令服务
- 对接同一套 WebRTC / MSS 协议
- 以 Electron 外壳分发（内含屏幕捕获选择器），同一份界面也可直接用浏览器打开

### 服务端

- 以官方 TeamSpeak 服务端为基础做适配
- 在服务端侧补充或抽象身份、房间、权限与屏幕共享信令能力
- 让三端都用统一的 roomId、clientUid、peerId 方案
- 提供 WebSocket 信令、房间管理、可扩展权限和 NAT 处理

## 3. 不再使用官方客户端的原因

我们的目标不是“接管官方客户端”，而是建设独立产品栈：

- 避免依赖官方桌面端私有协议
- 让 Android / PC 端都可以在统一协议上互通
- 屏幕共享可完全控制，而不受官方桌面端限制
- 让服务端适配得更透明、更可扩展

## 4. 协议策略

### 语音

- 使用 TeamSpeak 原生协议（ts3j 客户端库 + Concentus 的 Opus 编解码），因此语音链路与官方
  服务端、官方客户端完全互通，无需自研兼容层
- 音频为 Opus 20ms 帧，码率由频道的 `codecQuality`（0-10）映射
- 官方语音能力全部覆盖：静音/按键说话/声音激活、AEC/NS/AGC、离开状态、频道指挥、
  优先发言、发言申请、单人静音与音量、面向频道与用户的耳语、指挥组耳语

### 屏幕共享

- 继续使用现有 MSS 协议
- WebSocket 信令 + WebRTC 媒体
- 使用 TeamSpeak 服务器 UID + 频道 ID 派生 roomId
- 共享方和观看方通过同一 room 自动发现彼此
- 这部分不与官方客户端互通（官方信令层未公开）

## 6. 推荐的下一步

建议先把三端的界面风格和产品术语统一，例如：

- 服务器列表
- 频道树
- 用户列表
- 聊天区
- 屏幕共享区域
- 设置与高级选项

然后在 UI 之外重构协议和服务端适配层，使三端都遵循同一规范，避免后期又因 UI 与协议不一致导致重做。

## 7. 结论

TeamSpeak9 的总体思路是：

- 独立研发
- 兼容 TeamSpeak 用户习惯
- 不依赖官方应用
- 继续使用当前已经验证的 MSS/WebRTC 屏幕共享协议
- 服务端层做官方服务端适配扩展，保证三端统一

## 8. 实现现状

已完成：

- 三端目录拆分（`mobile/` `desktop/` `server/`）与统一配色 token
- Android 端全部界面与完整语音功能（详见 [../README.md](../README.md) 的语音功能对照表）
- 桌面端 Electron 外壳（内置屏幕捕获选择器，Windows 抓系统声音）+ 同一界面的浏览器模式
- 桌面端浏览器界面（官方风格三栏布局）+ 共享/观看
- 单一信令实现，桌面端与独立部署共用，10 个协议测试 + 端到端 smoke test
- 令牌准入、观众配额、UID 白名单、心跳驱逐
- CI 双 job（Android assemble/单测 + Node 协议测试）

未完成：

- SFU 中转（服务端侧；客户端已就绪，当前恒定回退 P2P）
- 耳语与真实 TeamSpeak 服务端的端到端联调（含组耳语的服务端权限校验路径）
